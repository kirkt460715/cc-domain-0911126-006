# 服务时长预测研究设计（forecasting）

## 1. 目的与边界

本研究只产出**排班参考**的有效服务时长预测，不自动改派单、不改员工工时。
预测目标是从 `started` 到 `completed` 之间扣除暂停后的有效服务秒数，即
重放结果中的 `active_seconds`（活跃区间并集时长），与 worktime 模块同一口径。

## 2. 点时信息截点与防泄漏

每条样本对应一次服务请求，信息截点固定为该请求的 `requested_at`：

- 特征仅含截点当时可知的量：`service`、`region`、`weekday`、`hour_of_day`，
  以及同一客户在截点前已完成、且完成事件 `observed_at <= requested_at`
  的历史服务摘要（次数、均值、中位数、同服务均值）。
- 明确禁止入特征：本单完成状态、未来事件修订、本单暂停、事后认领员工、
  当前已耗时、任何 `observed_at` 晚于截点的字段。
- 标签不使用截点信息，而是按研究给定的业务截止 `effective_at` 与知识截止
  `knowledge_at` 双截止重放得到。知识截止决定能看到哪个事件 revision，
  业务截止决定状态机推进到哪里。

实现上 `forecasting/dataset.py` 用增量可见事件表随请求时间推进，避免对每个
截点全量重放事件选择；含多修订或 void 事件的 visit 走按截点重放的通用路径，
保证修订语义不被性能优化破坏。

## 3. 互斥的不可训练原因

| 原因 | 含义 |
| --- | --- |
| `trainable_completed` | 时间线合法且已完成，有效秒数为正，唯一可训练类 |
| `incomplete_at_label_cutoff` | 业务截止时仍未完成（右截尾），不得拿当前已耗时当总时长 |
| `cancelled` | 已取消，取消不算完成 |
| `invalid_timeline` | 重放报告非法转移等时间线问题 |
| `non_positive_active_seconds` | 完成但有效秒数非正 |
| `not_requested_at_label_cutoff` | 业务截止之后才请求，该重放中尚不存在 |

排除记录保留在数据集与模型包内并计数，不进任何训练折。

## 4. 模型与变换

- **中位数基线**：按服务类型取训练集中位数；组样本不足时该服务不建组，
  预测时未见服务返回拒判而非伪造值。
- **岭回归**：目标做 `log1p(seconds)` 变换，类别 one-hot（低频类别不入词表），
  数值量按训练折均值/标准差标准化并记录支持域 `[min, max]`；正规方程 +
  L2 惩罚（不正则化截距），高斯-若尔当消元求解。预测 `expm1` 反变换回秒，
  所有指标都在秒口径计算。

## 5. 时间向前验证与客户去重

- 合成数据的训练客户每 4 周在两个互斥子集间轮转，相邻时间块客户不相交，
  使每个向前折的训练块与验证块天然无共享客户；同一客户在块内仍多次请求，
  保留客户历史特征。
- `forecasting/splits.py` 仍执行通用去重：验证侧若出现训练侧客户，删去该
  验证记录，并在折报告 `purge` 中列出具体 visit、客户数与代价说明。
- 校准段（4 周）与最终测试段（2 周）时间更晚，使用与训练互不复用的客户队列；
  测试侧再与校准侧去重。所有剔除代价写入模型包。

## 6. 单侧时长上界与校准

- 残差 = 实际秒数 − 点预测秒数（秒口径），在校准集上取上分位数。
- 有限样本规则取第 `ceil(coverage * (n+1))` 个次序统计量（1 基）；该秩超过
  `n` 时判定校准集不足以支撑所选覆盖率，`supported=false` 并写明最少观测数，
  不退化用样本最大值冒充高覆盖上界。
- 评估输出 MAE、pinball 分位数损失、经验覆盖率、违约次数与超时幅度（均值/
  最大值），按时间段、服务类型分组并单列新客户。

## 7. 拒判与保守基线策略

- 未见服务类型：`abstain / unseen_service_category`，不返回精确值。
- 数值特征超出训练支持域：`abstain / numeric_feature_outside_training_support`。
- 新客户（历史完成数为 0）但服务类型见过：正常给点预测并标记 `new_client`，
  由校准上界吸收其更高不确定性，不静默套用老客户精度。
- 校准不支持所选覆盖率：点预测照给，上界为 `null` 且 `upper_bound_supported=false`。

## 8. 冻结模型包与版本规则

模型包（`forecasting/training.py`）含特征定义、标签口径与排除计数、拆分归属
（含剔除代价）、目标变换与标准化参数、类别词表、两个模型、校准上界、超参
选择记录、评估结果、原始事件摘要（计数、多修订事件、void、观测延迟）与
输入指纹；落盘带 sha256 清单和包摘要，重载后预测与冻结时逐字段一致。
后补事件改变输入指纹，按 `versioning_rule` 只能产出新版本包，不就地改写。

## 9. 已验证的三类边界（tests/test_forecasting.py）

1. **未来修订泄漏**：注入的完成事件 revision=2 在知识截止后才登记；截点特征
   看不到它，早知识截止按 rev1 打标签、晚知识截止按 rev2 打标签，二者不同。
2. **同一客户多次请求**：同客户不跨进同折训练/验证，跨界线记录显式剔除并
   记录代价；训练侧样本不被去重削减。
3. **全新服务类型**：`install` 只在最终测试期出现，两个模型都拒判且不返回
   秒数；已见服务正常返回秒级预测与上界。

## 10. 已知局限

- 岭模型为线性加性模型，无法表达客户与服务的强交互；新客户的数值历史特征
  为空时主要靠类别项与校准上界兜底。
- 合成数据为本地确定性生成，参数（暂停概率、客户乘子、队列规模）是研究
  假设而非实测分布；接入真实事件前需用同一套点时构建器重跑并复核覆盖率。
- 单侧上界假设校准残差分布对测试期稳定；分布漂移会体现为经验覆盖率偏离
  目标值，负责人应先看覆盖率再看点预测。
